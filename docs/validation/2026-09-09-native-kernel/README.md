# Native C128 boot, allocator and memory workspace — 2026-09-09

This checkpoint adds a separate native kernel and a dual-screen memory
workspace. It does **not** migrate or replace the legacy graphical desktop,
Ultimate applications or full productivity suite. The broader completion goal
and R3 platform stage remain open. See the [native ABI](../../NATIVE-KERNEL.md)
and [completion roadmap](../../IMPLEMENTATION-ROADMAP.md).

## CPU and fault coverage

[cpu-heap.json](cpu-heap.json) records 692 assembled-kernel calls, with 50
paired bank-boundary transfer cases and 1,608 interrupt attempts/deliveries.
The model executes the installed Commodore native ROM gateways, including
their actual common-RAM instructions and native IRQ/NMI restore path.
ROM: `kernal-318020-05.bin`, SHA-256
`64ed21ad31da2840aa90eab70c6ed4731f63268a1b3c5cf85273e28d6cfa6d4d`.

Covered behavior:

* Exhaust both pools (191 + 251 pages), then recover all 442 pages; exhaust
  the 32 handle slots, reserve fixed ranges and exercise fragmented first fit.
* Reject stale/wrong-owner handles, increment through generation carries and
  retire the final generation rather than reissue a prior handle.
* Transfer to identical addresses in both banks, including RAM beneath ROM
  and I/O, page crossings, 512-byte calls and the final managed byte `$feff`.
  Compare host-generated bytes and guards; reject invalid counts and overflowing
  offsets before data changes. Preserve decimal/interrupt flags and scratch.
* Reject bad records/page tags, preflight owner-wide release without partial
  cleanup, preserve foreign owners and reject reentry without changing the
  active mailbox/lock. Unsupported MMU/page mappings return platform errors.
* Inject NMI at each native bank-gateway instruction boundary, and attempt
  IRQ at those masked boundaries. Separately deliver IRQ between every byte
  of each 512-byte read/write/fill, preserving the native MMU/register frame.

This is a focused bus model, not a complete C128 or peripheral emulator.
Injected handlers count and use the actual native restore stub; they do not
certify every KERNAL NMI device handler or third-party interrupt extension.

[cpu-capture.json](cpu-capture.json) covers 19 complete native IRQ observer
cases: both RAM banks including I/O/ROM overlap, VDC readiness/address drift,
timeouts, repeated drift, invalid commands/counts and guard bytes. It verifies
the extra native MMU stack byte, register/flag/pointer restoration, original
IRQ chain, VDC update-address restoration and zero writes to captured data.

## x128 cold boot and integration

[emulator/report.json](emulator/report.json) and
[regressions/report.json](regressions/report.json) pass using the final images.
x128 starts with the D64 already in its 1541 and uses the actual native KERNAL
boot-sector path. There is no `-go64`, injected kernel entry or PRG autostart.

The suite allocates, fills and verifies separate 8 KiB blocks in both banks,
compares complete bytes through VICE's independent `ram00`/`ram01` monitor
banks, switches back to each retained block and releases both. All pages and
slots return. Complete 1,000-cell VIC and 2,000-cell VDC screens match a host
oracle. The native observer agrees with direct VICE RAM/VDC memory, restores
its scratch and IRQ state, and the foreground still consumes keys afterward.
Raw common-RAM gateways and both banks' top-page stubs are retained as evidence.

## Physical reference C128 + Ultimate II+

[hardware/report.json](hardware/report.json) is a terminal **PASS**. The run
started from the idle deployed legacy desktop, mounted the native D64 on drive
A, used machine reset and left a full 60 seconds for IEC boot traffic before
RAM DMA observations. The same quiet interval was used when restoring the
legacy system. Native keyboard input uses `$034a/$d0`, not the C64 buffer.

Physical results:

* Native cold boot and MMU state are confirmed by CPU instructions: mode
  register `$37` has C64 mode clear, common configuration is `$04` and the
  interrupted foreground mapping is `$0e`.
* Both 8 KiB blocks pass the workspace's fill/verify workflow. Independent
  readback matches **all 16,384 bytes**: bank 0 via cartridge DMA, bank 1 via
  a read-only native KERNAL observer independent of the heap transfer routine.
* Initial, allocated and released screen states match every visible VIC/VDC
  cell. Each VDC sample is acquired twice and the pair must agree. All six
  VDC captures and five RAM1 chunks complete without address resynchronization.
* Seventeen key events include invalid-handle reporting, allocations,
  verification, bank switches, release and continued input after observations.
  All 442 pages and 32 handles are free at the end.
* Every observation restores borrowed RAM and the IRQ vector and checks the
  heap/mailbox remained unchanged. The native observer is installed only in
  reserved system RAM while the workspace is idle; it is not a general sampler
  for arbitrary future apps or concurrent display activity.
* The legacy distribution is remounted on A and its live desktop is confirmed.
  Its nine-byte settings record is preserved. Drive B, software IEC and printer
  inventory remain unchanged. No cartridge filesystem commands or USB fixture
  files are created. Build hashes remain unchanged throughout.

The mounted system image on A uses a fresh firmware `/Temp` name on restoration;
its contents are the unchanged legacy distribution. This run does not address
the separately documented inaccessible long-name USB fixture from an earlier
file-service checkpoint.

## Development failure and remaining work

The first x128 attempt reached the native workspace but returned platform error
8. The MMU check incorrectly required unused high bits of page-pointer registers
to read zero. Native readback is `$f0`. The implementation now masks unused
high bits, while still rejecting nonzero bank/page selections. The failed input
disk, registers and screen remain under [before-platform-fix](before-platform-fix/).
The final emulator and physical checks above use the corrected image.

Native app loading/manifests, cooperative scheduling, the graphical desktop,
Ultimate and IEC shared services, banked documents, 2 MHz/DMA regions and REU
ownership remain implementation work. Full-memory destructive hardware tests,
extended IRQ/NMI/load soak and C128D/DCR/other-ROM qualification remain coverage
gates. Neither software models nor this one reference C128 establish universal
hardware support or GEOS/Wheels application parity.
